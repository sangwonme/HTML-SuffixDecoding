\section*{1. 한 장 요약}
\subsection*{핵심 결과 5개}
\begin{enumerate}[leftmargin=1.3em]
\item \textbf{구조 규칙은 실제 GPU 시간에서 prompt lookup보다 약 7\% 빠르고, HTML 표현을 바꿔도 대체로 유지된다.}
 원래 형식 +6.95\% [+4.06, +10.00], 요청 50개 × 3회. 재실행 +6.76\% [+3.73, +9.89].
 예시와 출력 형식을 모두 바꾼 조건 A에서는 네 변형 모두 유의하다: 서식 +6.4\% [+0.4, +12.7], CSS 인라인 +11.9\% [+6.4, +16.8], 래퍼 추가 +6.9\% [+4.2, +9.6], 클래스 이름 +6.2\% [+1.2, +10.7].
 초안 원천만 바꾼 조건 B에서는 초 단위로 셋이 유의하고, 래퍼 추가는 +0.18초 [−0.03, +0.37]로 유의하지 않다.
 \textbf{단, 독립 test 100개에서는 규칙 단독 이득이 +2.3\% [−2.9, +6.7]로 유의하지 않다.} 호출당 토큰은 +10\% 높지만, 48개 요청에서 출력이 수치 차이로 갈라져 규칙 쪽 출력이 평균 34토큰 길었다.
 \textbf{다른 HTML 출처인 WebSight 50개에서도 규칙 이득은 남는다.} 요청당 +1.51초 [+0.14, +2.81], 호출 +4.17\% [+0.71, +7.38]로 유의하다. 요청별 비율로는 +3.22\% [−0.24, +6.46]로 0을 조금 포함한다.
\item \textbf{학습 순위 모델은 원래 형식에서 규칙보다 실측 5.1\% 빠르지만, 형식이 바뀌면 이득이 사라지거나 뒤집힌다.}
 원래 형식 +5.1\% [+1.8, +8.1], 초 단위 +0.29초 [+0.05, +0.53]. 조건 A 서식 변환에서 −11.5\% [−27.8, −1.1]로 더 느리고, 나머지 세 변환은 유의하지 않다. 조건 B에서는 클래스 변환만 유의하다, +0.25초 [+0.07, +0.45].
 \textbf{외부 데이터 WebSight에서는 규칙 대비 이득이 없다.} 규칙 − 학습 −0.53\% [−3.35, +2.22]. lookup 대비 +3.50\% [+0.85, +5.97]는 규칙의 몫과 같은 크기다.
\item \textbf{정식 SuffixDecoding은 우리 방법 단독보다 훨씬 강하다. DOM 특징을 더한 추가 이득은 1--3\%로 작다.}
 재생 분석, 주 데이터 114개, 요청당 모델 호출 수: 학습 모델 단독 121.8, 공식 규칙 SD 기본 설정 108.1, 튜닝 94.3.
 SD에 학습 순위 모델을 더한 이득은 튜닝 설정에서 2.9 [2.25, 3.61], 즉 −3.1\%이고, 초안 상한 64에서는 0.96 [0.40, 1.54]이다. 공식 기본 설정에서는 주 데이터에서 0.52 [0.14, 0.89]이고, 데이터 세트 셋 중 둘에서는 유의하지 않다.
 DOM 특징만의 몫은 0.96--1.70 호출이다. GPU 실측은 아직 없다.
\item \textbf{SD의 전역 캐시 이득은 누수가 아니다.}
 평가 요청 174개 모두 같은 요청, 같은 앱, 정답과 똑같은 출력이 캐시에 0개였다. 실제 서빙 순서로 캐시를 쌓아도 prompt lookup 대비 이득의 79\%가, 상용구를 지워도 82\%가 남는다.
\item \textbf{처음 보는 앱에서도 학습 모델이 규칙과 표준보다 실측으로 빠르고, 품질은 같다.}
 train 앱 150개로만 학습한 모델을 pilot과 겹치지 않는 test 100개 요청, 앱 92개에서 1회 실측했다. 시간은 lookup 5.28초, 규칙 5.17초, 학습 모델 4.86초. 규칙 − 학습 +5.9\% [+3.2, +8.7], 요청당 +0.31초 [+0.08, +0.58]. lookup − 학습 +9.5\% [+5.0, +13.3]. 체크리스트 0.94, 요소 F1 0.59로 정책 간 차이는 ±0.01 이내이고 유의하지 않다. 단, 이것은 같은 S2W 변환기 형식 안의 일반화다. 다른 출처인 WebSight에서는 학습 모델이 규칙과 같다.
\end{enumerate}

\begin{itemize}[leftmargin=1.2em]
\item \textbf{주 기여:} 구조 규칙은 다른 HTML 출처에서도 lookup보다 빠르다. 학습된 구조 조건 초안 선택은 같은 HTML 출처의 처음 보는 앱에서 규칙보다 5.9\%, 표준보다 9.5\% 빠르고 품질을 유지한다. 다른 출처인 WebSight에서는 학습 모델의 추가 이득이 없다.
\item \textbf{충족된 조건:} 독립 test에서 학습 모델이 규칙보다 느리지 않을 것. 충족했다.
\item \textbf{남은 조건 두 가지:} SD + DOM의 GPU 실측 이득 확인, 그리고 서식 변화와 다른 출처에서 학습 모델의 강건성 회복. 실패하면 SD 위의 추가 이득과 형식 및 출처 일반화는 주장에서 뺀다.
\item \textbf{다음 연구 후보:} 전역 캐시까지 포함한 위치 검색. 로컬 문맥 오라클 74.5 대비 전역 포함 오라클 46.9 호출로, SD 튜닝 94.3과의 격차가 가장 크다.
\item \textbf{멈출 것:} ``구조 정보만으로 SuffixDecoding을 이긴다''는 주장, 형식 변화나 다른 HTML 출처에서 학습 모델이 강건하다는 주장.
\end{itemize}

\section*{3. 확인된 사실과 가설}
\textbf{확인된 사실, 신뢰구간 > 0}
\begin{itemize}[leftmargin=1.2em]
\item 구조 규칙은 GPU 실측에서 prompt lookup보다 빠르고, 조건 A 네 변형에서도 유지된다.
\item 학습 모델은 원래 형식에서 규칙보다 GPU 실측으로 빠르다. 처음 보는 test 앱 100개 요청에서도 규칙보다 +5.9\%, lookup보다 +9.5\% 빠르고 품질이 같다.
\item 다만 독립 test에서 규칙 단독의 lookup 대비 이득은 +2.3\%로 유의하지 않다.
\item 다른 HTML 출처인 WebSight에서도 규칙은 lookup보다 요청당 +1.51초, 호출 +4.2\%로 유의하게 빠르다.
\item WebSight에서 학습 모델은 규칙보다 빠르지 않다. 차이는 −0.5\%이고 유의하지 않다. 학습 모델의 이득은 S2W 변환기 형식 안에서만 확인됐다.
\item 구조 특징을 빼면 학습 모델이 나빠진다. 재생 분석이다.
\item 정식 SD 튜닝 설정 위에 학습 모델을 더하면 호출이 1--3\% 준다. 재생 분석이다.
\item SD의 전역 캐시 이득은 누수나 상용구로 설명되지 않는다.
\item 정확 검증에서는 한 단계 최선 선택이 다단계 계획과 같다. 70개 출력 모두 차이 0이다.
\end{itemize}
\textbf{가설, 아직 검증하지 않음}
\begin{itemize}[leftmargin=1.2em]
\item SD + DOM의 1--3\% 이득이 GPU 시간에서도 남는다. 튜닝 설정은 호출당 검증 토큰이 13.5개라 시간 이득이 줄 수 있다.
\item 전역 캐시를 포함한 위치 검색이 오라클 격차 94.3 → 46.9의 일부를 메울 수 있다.
\item 형식이 섞인 데이터로 학습하거나 형식 의존 특징을 정규화하면 서식 변환 실패를 막을 수 있다.
\item 외부 출처 데이터를 섞어 학습하면 WebSight에서도 학습 모델의 이득이 생긴다.
\item WebSight에서 규칙 이득이 작은 것은 출력이 정답보다 길고 예시와 덜 겹쳐 초안이 덜 맞기 때문이다.
\end{itemize}

\section*{4. 실패 사례와 원인}
\begin{itemize}[leftmargin=1.2em]
\item \textbf{서식 변환에서 학습 모델이 규칙보다 느리다.} 모델이 예시에 없는 방식으로 \texttt{<style>} 안 CSS까지 줄바꿈한다. 예시 CSS에서 가져온 초안이 맞지 않아 평균 수락 길이가 3.99에서 1.51로 떨어진다. 깊이, 형제 순번, 최근 수락 길이가 학습 범위를 벗어나 MLP가 잘못 보정된다. 초안 원천만 바뀐 조건 B에서는 실패하지 않으므로 출력 쪽 분포 이동이 원인이다.
\item \textbf{SD의 전역 캐시 우위.} 우리 방법은 요청 안의 문맥만 쓰고 SD는 다른 요청의 출력을 쓴다. 이전의 ``변환기 형식 공유가 SD를 유리하게 했을 것''이라는 해석은 반박됐다. 형식을 바꿔도 SD 이득은 래퍼 추가를 빼면 유지되거나 커졌고, 상용구를 지워도 82\%가 남았다.
\item \textbf{공식 기본 설정에서 SD + DOM 이득 소멸.} 초안이 짧거나 길 때 SD의 빈도 기반 선택이 이미 잘 맞는다.
\item \textbf{빠른 예시를 미리 고르는 학습 실패.} 시간 차이의 75\%가 출력 길이에서 오고, 생성 전 특징의 상관은 모두 0.13 이하다.
\item \textbf{화면 기준 수락의 여지가 작다.} 거절된 초안 중 같은 화면을 만드는 것은 6--18\%뿐이다.
\item \textbf{WebSight에서 학습 모델의 이득이 사라진다.} 규칙 − 학습은 −0.53\% [−3.35, +2.22]다. 학습 데이터가 S2W 변환기 형식뿐이다. 특징 분포를 비교하는 원인 분석은 아직 하지 않았다.
\end{itemize}

\section*{5. 다음 작업 우선순위}
\begin{enumerate}[leftmargin=1.3em]
\item 독립 test에서 규칙과 lookup의 차이를 3회 반복 또는 같은 출력 기준 재생으로 다시 확인한다.
\item SD + DOM의 GPU 실측. 공식 모듈 빌드 승인이 필요할 수 있다.
\item 학습 모델 개선: 형식 혼합 학습, WebSight pool 150개를 섞은 학습, 형식 의존 특징 정규화, 이력 특징 제거.
\item 새 방향: 전역 캐시를 포함한 위치 검색.
\end{enumerate}

\section*{6. 사용자 결정이 필요한 사항}
\begin{itemize}[leftmargin=1.2em]
\item \textbf{공식 SuffixDecoding C++ 모듈 빌드 승인.} 격리된 폴더에서 외부 코드를 빌드하고 실행해야 하는데 권한 정책에 막혔다. 승인하면 공식 구현으로 재생 분석을 교차 검증할 수 있다. vLLM 서빙 경로는 Windows에서 동작하지 않는다.
\item \textbf{코드 라이선스.} 공식 SuffixDecoding은 Apache-2.0이다. 우리 코드는 공식 코드를 복사하지 않고 규칙만 다시 구현했다. 우리 저장소의 라이선스를 정해야 한다.
\item \textbf{데이터 공개 범위.} 데이터는 Screen2Words와 RICO, CC-BY-4.0에서 파생했다. 파생 데이터, 모델 출력, 학습 가중치의 공개 범위를 정해야 한다.
\end{itemize}
